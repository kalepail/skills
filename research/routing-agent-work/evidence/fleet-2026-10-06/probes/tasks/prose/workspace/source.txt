When the fleet daemon was upgraded to v4.12.0 last quarter, the routing table that had previously been stored in several scattered files was consolidated into a single file at /etc/fleetd/routes.toml, which is read once at startup and then cached in memory until the process is restarted or a reload signal is received from the supervisor. Operators who were accustomed to editing the old files directly were advised that any change should first be validated by running the reload command with the --dry-run flag, because a malformed entry that was not caught before the reload would cause every worker in the pool to fall back to the default route, and that fallback was found during the incident review to cost roughly $0.35 per thousand requests in extra upstream charges. The reload command prints a diff of the routes that would change, and it exits with a nonzero status if any entry cannot be parsed, so it can be wired into a pre-commit hook without much effort. Older entries that were written for the previous schema were automatically migrated, but entries that referenced retired regions were dropped and logged as warnings.
